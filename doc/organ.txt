INTRODUCTION                                              *organ-introduction*

organ.nvim is a unified org-mode + org-roam implementation for Neovim.
It uses a tree-sitter grammar (`tree-sitter-organ` + `tree-sitter-organ-
inline`, separate public repos) for parsing and SQLite for indexing
headlines, links, properties, and timestamps.

Feature set (pre-1.0, daily-driver parity with Emacs):
 - TODO cycling, agenda, capture, clocking
 - Links, refile, backlinks
 - org-roam nodes, dailies
 - Properties, tag inheritance
 - Sparse trees
 - Tables: auto-align, row/col operations, formulas

Explicitly deferred: Babel, export, org-roam graph.

Status: Pre-1.0. API may change before 1.0. Feedback welcome.

==============================================================================
REQUIREMENTS                                              *organ-requirements*

 - Neovim 0.11+ (uses `nvim_set_option_value`, `vim.uv`, `conceal_lines`
   extmarks, etc.)
 - SQLite 3 runtime — FFI-loaded; no Lua binding required. Linux/macOS
   ship it; Windows users may need to install it separately.
 - `git` + `make` + a C compiler to build the tree-sitter grammars.
   No Node / npm / pnpm needed: each grammar repo commits the
   generated parser.c; install clones the repos and runs `make`.

==============================================================================
INSTALLATION                                              *organ-installation*

With lazy.nvim: ~
>lua
    {
      "sakakibara/organ.nvim",
      dependencies = { "sakakibara/tablature.nvim" },
      build = function() require("organ.grammar_install").install() end,
      config = function()
        require("organ").setup({
          org_dir = vim.fn.expand("~/org"),
        })
      end,
    }
<

With vim.pack (Neovim 0.12+ built-in, no third-party manager): ~
>lua
    vim.pack.add({
      "https://github.com/sakakibara/tablature.nvim",
      "https://github.com/sakakibara/organ.nvim",
    })
    require("organ.grammar_install").install()  -- one-time; idempotent
    require("organ").setup({
      org_dir = vim.fn.expand("~/org"),
    })
<

The build step clones `tree-sitter-organ` + `tree-sitter-organ-inline`
into `<stdpath data>/organ/`, compiles the parsers into
`<stdpath data>/organ/parser/{org,org_inline}.so`, and registers them
via `vim.treesitter.language.add` lazily (on first tree-sitter call,
not at `setup()` time). nvim-treesitter is NOT required.

`plugin/organ.lua` runs at Neovim startup and registers all `:Org*`
commands. No DB or tree-sitter work happens at this stage, so startup
time is unaffected regardless of how many org files you have.

`ftplugin/org.lua` installs buffer-local keymaps when a buffer's
filetype is set to `org`.

QUICKSTART                                                  *organ-quickstart*

Commands to try first:
>vim
    :Org scan              " index org_dir into SQLite
    :Org agenda            " open the default agenda view
    :Org find              " fuzzy-find headlines
    :Org capture           " run a capture template
    :Org clock in           " start a clock on the headline at cursor
    :Org roam daily today    " open today's daily note
<

Default global keymaps (from any buffer):

    `<Leader>oc`   |:Org-capture|
    `<Leader>oa`   |:Org-agenda|
    `<Leader>of`   |:Org-find|
    `<Leader>or`   |:Org-roam|
    `<Leader>od`   |:Org-roam_daily_today|
    `<Leader>oi`   |:Org-clock_in|
    `<Leader>oo`   |:Org-clock_out|

See |organ-config-global-keymaps| for the full table.

CONFIGURATION                                                   *organ-config*

All configuration is passed to `require("organ").setup({...})`.

------------------------------------------------------------------------------
Conventions                                         *organ-config-conventions*

Five rules govern how config works:

1. List/map collections REPLACE on user override. ~
   `capture.templates`, `agenda.views`, etc. — provide your own list to
   fully replace defaults. Compose with defaults via: >lua
       local defaults = require("organ.defaults")
       require("organ").setup({
         capture = {
           templates = vim.tbl_extend("force",
             defaults.capture.templates, {
               { name  = "My Note", key = "x",
                 target = { kind = "file",
                            path = "~/org/scratch.org" },
                 body  = "* %?" },
             }),
         },
       })
<

2. Keymap blocks DEEP-MERGE. ~
   Set `keymaps.<name> = "<lhs>"` to override a single key.
   Set `keymaps.<name> = false` to disable that one binding.
   Set `keymaps = false` to disable all keymaps for a feature.

3. Every feature has `enabled = true`. ~
   Set `<feature>.enabled = false` to turn it off: keymaps not
   installed, autocmds not registered, and the feature's `:Org*`
   commands removed from Neovim's completion list.
   Exception: `watcher.enabled = false` means "don't auto-start"; the
   `:Org watch_*` commands stay registered.

4. `nil` is "absent". ~
   To disable something use `false`, not `nil`. `vim.tbl_deep_extend`
   strips nil values.

5. Defaults are public. ~
   `require("organ.defaults")` returns the canonical default config.
   Inspect, copy, or compose from it.

Examples: >lua
    -- Disable property editing entirely
    require("organ").setup({ property = { enabled = false } })

    -- Override one keymap
    require("organ").setup({
      structure = { keymaps = { promote_subtree = "<Leader>op" } },
    })

    -- Disable all subtree keymaps
    require("organ").setup({ structure = { keymaps = false } })
<

Defaults                                               *organ-config-defaults*

Top-level options:

                                                *organ-config-scan_on_startup*
    `scan_on_startup` (bool, default: `false`)
    If `true`, run a scan on every Neovim startup.

    Milliseconds to debounce file-change events.

                                                    *organ-config-incremental*
    `incremental` (bool, default: `true`)
    Only reindex changed files.

                                                     *organ-config-mtime_skip*
    `mtime_skip` (bool, default: `true`)
    Skip files whose mtime hasn't changed.

                                                      *organ-config-hash_skip*
    `hash_skip` (bool, default: `true`)
    Skip files whose content hash matches the stored hash.

                                                   *organ-config-auto_recover*
    `auto_recover` (bool, default: `true`)
    Auto-recover from DB corruption.

                                                   *organ-config-ignore_globs*
    `ignore_globs` (list, default: `{"**/archive/**", "**/.git/**", ...}`)
    Glob patterns for paths to skip during scan.

                                                *organ-config-scan_batch_size*
    `scan_batch_size` (number, default: `50`)
    Files per batch during a scan.

                                                         *organ-config-notify*
    `notify` (bool, default: `true`)
    Show `vim.notify` messages for scan results, errors, etc.

                                                      *organ-config-log_level*
    `log_level` (string, default: `"info"`)
    Log level for internal messages.

                                                        *organ-config-pragmas*
    `pragmas` (table)
    SQLite PRAGMA settings. Defaults: WAL journal, NORMAL synchronous,
    64 MB mmap, 5 s busy_timeout, foreign keys ON.

Capture                                                 *organ-config-capture*

                                                *organ-config-capture-enabled*
    `capture.enabled` (bool, default: `true`)

                                              *organ-config-capture-templates*
    `capture.templates` (list)
    List of capture template tables. Each entry has:

    `name`    Display name shown in the picker.
    `key`     Single character to activate this template directly.
    `target`  Where to file the entry. See target kinds below.
    `body`    Template string with placeholders.

    Target kinds:
     - `{ kind = "file", path = "~/org/notes.org" }` — append to file.
     - `{ kind = "file_headline", path = "...", headline = "Tasks" }`
       — append under named headline.
     - `{ kind = "file_olp_datetree", path = "..." }` — datetree.

    Placeholder reference:
     `%t`        Inactive timestamp `[YYYY-MM-DD Day]`
     `%T`        Active timestamp `<YYYY-MM-DD Day>`
     `%u`        Inactive timestamp + time
     `%U`        Active timestamp + time
     `%a`        Annotation (link to current file + line)
     `%i`        Initial content (from clipboard / selection)
     `%?`        Cursor position after template expansion
     `%^{Prompt}` Prompt user for a value
     `%<format>` Date formatted with `os.date(format)`

    Default templates: Task (`t`), Note (`n`), Journal (`j`).

                                    *organ-config-capture-jump_after_finalise*
    `capture.jump_after_finalise` (bool, default: `false`)
    If `true`, jump to the filed entry after finalising.

                                                 *organ-config-capture-window*
    `capture.window` (table)
    Controls the capture buffer window:
     - `kind`: `"float"` | `"split"` | `"vsplit"` (default: `"float"`)
     - `width`: float 0–1 (fraction of screen) or integer columns.
     - `height`: float 0–1 or integer rows.
     - `border`: `"rounded"` | `"single"` | `"double"` | etc.
     - `title`: window title format string.
     - `title_pos`: `"center"` | `"left"` | `"right"`.

                                        *organ-config-capture-datetree_format*
    `capture.datetree_format` (list of strings)
    `os.date` format strings for each datetree level.
    Default: `{ "%Y", "%Y-%m %B", "%Y-%m-%d %A" }` (year / month / day).

                                                *organ-config-capture-keymaps*
    `capture.keymaps` (table)
    See |organ-keymaps-capture|.

                                                  *organ-config-capture-popup*
    `capture.popup` (table)
    Template picker popup options (`border`, `width`, `max_lines`).

                                                 *organ-config-agenda-enabled*

                                            *organ-config-agenda-default_view*
    `agenda.default_view` (table)
    The view shown by |:Org-agenda| when no named view is selected.
    Fields:
     - `from`, `to`: date range. `"today"`, `"+7d"`, ISO strings.
     - `types`: list of `"scheduled"` | `"deadline"` | `"active"`.

     - `include_overdue` (bool): include overdue items.

    `blocks` list. Each block is a view table (same fields as
    `default_view`). Example: >lua
        agenda = {
          views = {
            weekly = {
              blocks = {
                { from = "today", to = "+7d",
                  types = { "scheduled", "deadline" },
                  todo = { exclude = { "DONE", "CANCELLED" } },
                  include_overdue = true, group_by = "day" },
              },
            },
          },
        }
<

     `vsplit`          vertical split     (`<C-v>`)
     `tab`             new tab            (`<C-t>`)
     `backlinks`       show backlinks     (`<C-b>`)
     `jump_to_source`  jump to source     (`<C-o>`)
     `create`          create new node    (`<M-CR>`)

Structure                                             *organ-config-structure*

                                              *organ-config-structure-enabled*
    `structure.enabled` (bool, default: `true`)

                                      *organ-config-structure-odd_levels_only*
    `structure.odd_levels_only` (bool, default: `false`)
    Mirror Emacs `org-odd-levels-only`: when `true`, only odd-
    numbered star counts (`*`, `***`, `*****`, ...) are treated as
    valid heading levels.  Promote / demote step by 2 stars instead
    of 1 so each step lands on the next valid level.

    Note: the tree-sitter grammar still parses `**` as a level-2
    heading -- this knob only changes promote / demote / move ops.
    Enabling it on a buffer with mixed-parity existing headings
    produces mixed-parity output until you normalise the buffer
    manually.

                                              *organ-config-structure-keymaps*
    `structure.keymaps` (table)
     `promote_subtree`   `"<<"` — promote subtree one level
     `demote_subtree`    `">>"` — demote subtree one level
     `promote_headline`  `<LocalLeader><` — promote headline only
     `demote_headline`   `<LocalLeader>>` — demote headline only
     `move_subtree_up`   `"gK"` — swap with previous sibling
     `move_subtree_down` `"gJ"` — swap with next sibling

TODO                                                       *organ-config-todo*

                                                  *organ-config-todo-sequence*
    `todo.sequence` (list or list-of-lists)
    Ordered list of TODO states. `"|"` separates active from done.
    Mirrors Emacs `org-todo-keywords`.
    Default: `{ "TODO", "NEXT", "WAITING", "HOLD", "PROJ", "|",`
              `"DONE", "CANCELLED" }`

    Two shapes accepted:

    Single sequence: ~
>lua
        sequence = { "TODO", "WAIT", "|", "DONE" }
<
    Multi-sequence (each sub-list has its own active->done): ~
>lua
        sequence = {
          { "TODO", "WAIT", "|", "DONE" },
          { "BUG", "TRIAGE", "|", "FIXED" },
        }
<
    Cycling stays within the matched sub-sequence (BUG cycles to
    TRIAGE then FIXED, never to DONE).

                                               *organ-config-todo-annotations*
    Each keyword may carry an Emacs-style annotation suffix in
    parentheses controlling the fast-selection key + log policy:

        `"TODO(t)"`        `t` = fast-selection key
        `"NEXT(n!)"`       `!` log timestamp on entry
        `"WAIT(w@)"`       `@` log + prompt for note on entry
        `"DONE(d/!)"`      `/!` log timestamp on EXIT
        `"DONE(d@/!)"`     prompt + note on entry, time on exit
        `"REPORT(@)"`      no key, only log policy

    Annotation-derived log policy is applied automatically -- no
    separate `log_states` entry needed for the common case.
    Explicit `log_states` overrides annotations.

                                               *organ-config-todo-fast-select*
    Fast-selection (Emacs `org-fast-todo-selection`) is invoked by:

        `<M-T>`             ergonomic chord (most terminals)
        `<LocalLeader>T`    universal fallback (every terminal)
        `:Org todo fast`    explicit command

    Press the annotated key to apply that state, `<Space>` to
    clear, `<Esc>` to cancel.  When no keywords are annotated,
    falls back to a `vim.ui.select` prompt.

                                                  *organ-config-todo-log_done*
    `todo.log_done` (string, default: `"time"`)
    What to log when a TODO is marked DONE: `"time"` or `"note"`.

                                                *organ-config-todo-log_drawer*
    `todo.log_drawer` (string, default: `"LOGBOOK"`)
    Drawer name used for TODO state change log entries.

                                                *organ-config-todo-log_states*
    `todo.log_states` (table, default: `{}`)
    Per-destination-state logging policy. Maps a state name to one of
    `"time"`, `"note"`, or `false`. Mirrors Emacs per-keyword `(state .
    "@")` / `(state . "!")` syntax. Setting a state to `false` suppresses
    logging for that destination even if `log_state_changes = true`.
    Example: `{ WAITING = "note", HOLD = "time" }`.

                                         *organ-config-todo-log_state_changes*
    `todo.log_state_changes` (boolean, default: `false`)
    When true, every TODO state transition writes a timestamp entry to
    the log drawer (per-state `log_states` overrides still apply).

                                           *organ-config-todo-log_into_drawer*
    `todo.log_into_drawer` (boolean, default: `true`)
    When true, state-change log entries wrap inside `log_drawer`. When
    false, entries appear as bare list items immediately after the
    planning block. Mirrors Emacs `org-log-into-drawer`.

                                                   *organ-config-todo-keymaps*
    `todo.keymaps` (table)
    All default to `nil`:
     `cycle`  Cycle through TODO states
     `set`    Open picker to set TODO state

                                                 *organ-config-todo-calendars*
    `todo.calendars` (list, default: `{}`)
    Holiday calendar names used by repeater skip filters.

                                           *organ-config-todo-default_country*
    `todo.default_country` (string or nil)

Archive                                                 *organ-config-archive*

                                                *organ-config-archive-enabled*
    `archive.enabled` (bool, default: `true`)
    Gates `:Org archive` commands and the `<LocalLeader>$` keymap.

                                               *organ-config-archive-location*
    `archive.location` (string|function, default: `"%s_archive::"`)
    Where archived subtrees go.  Emacs `org-archive-location` syntax:
    `"FILE::HEADLINE"`.
      `FILE`      where to write entries.  `%s` is replaced with the
                  source file's basename (Emacs convention).  Relative
                  paths resolve against the source's directory;
                  absolute paths and `~/...` are honored as-is.

        location = "%s_archive::* Archive"  -- wrap under "* Archive"
        location = "~/.org/archive/%s::"    -- centralised archive dir
        location = "::* Old stuff"          -- same file, under "* Old stuff"
<
    May also be a function `(src_path) -> location_string` for
    dynamic destinations (e.g. dated archive dirs) -- an organ
    extension over Emacs's string-only `org-archive-location`.

    Override precedence at archive time:
      1. `:ARCHIVE:` property on the subtree being archived
      2. `#+ARCHIVE:` directive at the buffer top
      3. this config value

Fold                                                       *organ-config-fold*

                                                   *organ-config-fold-keymaps*
    `fold.keymaps` (table)
     `cycle`        `<Tab>` — cycle fold state of headline at cursor
     `cycle_global` `<S-Tab>` — cycle global fold state

    Note: `<Tab>` is shared with table navigation. When the cursor is
    on a table row it navigates cells; on a headline it folds.

                                                  *organ-config-fold-foldtext*
    `fold.foldtext` (string | function | false, default: `"emacs"`)
    Selects what `organ.fold.foldtext()` RETURNS when your
    `'foldtext'` option calls into it.  This setting only changes
    the return shape; whether organ writes the `'foldtext'` option
    is controlled by `fold.auto_foldtext` (off by default).

    Accepts:

        "emacs"     -- heading line + `…` suffix when the fold
                       hides real content (Emacs `org-ellipsis`
                       look).  All-blank body is left bare.
                       Returns treesitter-aware highlight segments
                       so the heading keeps its TODO / title / tag
                       colors when folded.
        function(foldstart, foldend) -> string | list -- custom
                       renderer.  Return a string for plain text,
                       or a list of `{text, hl_group}` tuples for
                       per-segment highlights.  Errors from the
                       function fall back to the heading line so a
                       buggy override can't break the buffer.
        false / nil -- defer to vim's builtin `foldtext()` (the
                       `+--  N lines: <line>` format).  Use this
                       to opt out of organ's emacs-style decoration
                       without writing a custom function.

                                             *organ-config-fold-auto_foldtext*
    `fold.auto_foldtext` (bool, default: `true`)
    When `true` (default), organ sets win-local `'foldtext'` on
    every org buffer to call into `organ.fold.foldtext()` -- a
    fresh install renders org-aware folded headings (treesitter
    colours + ellipsis) without any Lua.  Win-local + ftplugin-
    scoped, so non-org buffers always keep your global `'foldtext'`.
    Also overrides win-local `'fillchars.fold'` to space on org
    buffers (your other fillchars entries -- eob, vert, msgsep,
    etc. -- are merged through), since vim's default `·` filler
    draws a dotted line past organ's self-contained foldtext.

    Set `false` to keep your custom `'foldtext'` on org buffers
    too -- typical when your wrapper already delegates.  When you
    wire it yourself organ also stops touching `'fillchars'`; drop
    the dotted filler in your own config:
>lua
        vim.opt.fillchars:append({ fold = " " })
<
    Wire-it-yourself recipe:
>lua
        function MyFoldtext()
          if vim.bo.filetype == "org" then
            local ok, fold = pcall(require, "organ.fold")
            if ok then return fold.foldtext() end
          end
          return vim.fn.foldtext()
        end
        vim.opt.foldtext = "v:lua.MyFoldtext()"
<
    Same pattern as statuscolumn / statusline.  The auto-apply path
    is the no-Lua path; the wire-it-yourself path is for users who
    already have a custom `'foldtext'` wrapper they want to delegate
    from.  `:checkhealth organ` prints the recipe when neither path
    is in effect.

                                         *organ-config-fold-auto_statuscolumn*
    `fold.auto_statuscolumn` (bool, default: `true`)
    When `true` (default), organ sets win-local `'statuscolumn'`
    on every org buffer to a sensible default that uses
    |organ-fold-statuscolumn_marker| (correct fold chevron in
    OVERVIEW + CONTENTS) and the line number.  Includes `%s` for
    the signs column so gitsigns / diagnostic signs keep rendering
    on org buffers.  Win-local + ftplugin-scoped, so non-org
    buffers always keep your global `'statuscolumn'`.  Set `false`
    to keep your custom `'statuscolumn'` on org buffers too --
    pair with the helpers (`organ.fold.statuscolumn_marker` and
    `organ.fold.contents.statuscolumn_lnum`) for fold-aware
    rendering.

                                                        *organ-fold-OrgFolded*
    Folded org-buffer rows render with the `OrgFolded` highlight
    group instead of vim's default `Folded`.  organ defines
    `OrgFolded` with `bg = "NONE"` (default = true so user
    overrides win) and the org ftplugin sets window-local
    `'winhighlight'` to remap `Folded:OrgFolded`, so folded heading
    lines blend with `Normal` instead of vim's grey ribbon and the
    treesitter-aware foreground colors render on top cleanly.

    Gotcha: `winhighlight` is window-local and additive.  organ's
    ftplugin appends `Folded:OrgFolded` to whatever was already
    there (and skips if the user has their own `Folded:` entry).
    To override, either set your own `Folded:` mapping in
    `'winhighlight'` BEFORE the org buffer attaches, or override
    the `OrgFolded` group itself:
    >lua
        vim.api.nvim_set_hl(0, "OrgFolded", { bg = "#333333" })
<

    Body lines share the parent heading's foldlevel; each section is
    one fold; `za` on body folds the heading (Emacs).  CONTENTS view
    (`<S-Tab>` third state) hides body via `conceal_lines` extmarks,
    leaving every heading visible.  Auto-bumps `conceallevel` and
    `concealcursor` while CONTENTS is active and restores both on
    exit.  Each heading whose body is hidden also gets a virt_text
    `…` suffix (per-level heading-title hl via
    `@org.heading.title.<N>.org`, so the ellipsis matches the heading
    color) -- the heading line reads identically to its OVERVIEW
    counterpart where `emacs_foldtext` renders the same suffix on the
    closed fold.

                                              *organ-fold-statuscolumn_marker*
    `require("organ.fold").statuscolumn_marker(lnum)`
    Drop-in fold-marker function for custom statuscolumns that
    compute markers via `foldlevel(lnum) > foldlevel(lnum - 1)`.
    That idiom misses heading lines whose foldlevel doesn't strictly
    exceed the previous line's (sibling headings, or any heading
    after body in `body_fold = true` mode).  In an org buffer the
    helper marks every heading line as a fold-start regardless of
    the level transition and suppresses markers on body lines.
    Falls back to level-compare on non-org buffers.

    Pair it with |organ-fold-contents-view-statuscolumn_lnum| for
    correct relnum under CONTENTS view.  Recipe wiring both helpers:
    >lua
        local M = {}
        local function number_for(lnum, relnum, virtnum)
          if virtnum and virtnum ~= 0 then return "    " end
          local relative = vim.wo.relativenumber
            and relnum and relnum ~= 0
          local n
          local ok, contents = pcall(require, "organ.fold.contents")
          if ok and contents.statuscolumn_lnum then
            n = contents.statuscolumn_lnum(lnum, relative)
          else
            n = relative and relnum or lnum
          end
          return string.format("%4d", n)
        end

        local function fold_for(lnum)
          local ok, organ_fold = pcall(require, "organ.fold")
          if ok and organ_fold.statuscolumn_marker then
            return organ_fold.statuscolumn_marker(lnum)
          end
          return " "
        end

        function M.render()
          return table.concat({
            "%s",
            number_for(vim.v.lnum, vim.v.relnum, vim.v.virtnum),
            " ",
            fold_for(vim.v.lnum),
            " ",
          })
        end
        return M
<
    Then `vim.o.statuscolumn = "%!v:lua.require'lib.statuscolumn'.render()"`.

                                                    *organ-fold-contents-view*
CONTENTS view (`<S-Tab>` third state, body_fold = false strategy):
when active, the buffer is in a temporary mode where every heading
is visible at every depth and body lines are hidden.  Several
window/buffer treatments are applied for the duration; ALL of them
are reverted on exit.  No special state is allowed to leak past
this mode.

  Conceal layer       Body line ranges get a `conceal_lines = ""`
                      extmark in the `organ_fold_contents`
                      namespace.  Cleared on exit.

  Window options      `conceallevel` is auto-bumped to 2 (if lower)
                      and `concealcursor` is set to `nvic` so the
                      cursor sitting on a concealed line keeps it
                      hidden -- otherwise vim's default would reveal
                      body the moment `j` lands there.  Prior values
                      are saved per-window and restored on exit on
                      every window currently displaying the buffer.

  Cursor redirect     A buffer-local `CursorMoved` autocmd watches
                      every motion (j / k / arrows / gj / gk /
                      search / gg / G / `]]` / `[[` / marks /
                      mouse) and bounces the cursor off concealed
                      body to the nearest visible line in the
                      direction of travel.  Does NOT touch any
                      keymap; user remaps continue to work.
                      `BufWinEnter` is also wired so re-entering
                      the buffer's window via `:wincmd`, mouse, or
                      tmux focus also nudges the cursor off body.
                      Visual / insert / operator-pending modes are
                      left alone.

  Line numbers        Vim's built-in `'relativenumber'` counts
                      buffer lines, so a heading 5 buffer rows down
                      shows as "5" even when body is concealed
                      between -- visually wrong.  Use the helper
                      below from a custom statuscolumn to compute
                      number/relnum from VISIBLE-line distance.
                      Outside CONTENTS state no extmarks exist and
                      the helper returns vim-equivalent values, so
                      it's safe to wire unconditionally.

                                  *organ-fold-contents-view-statuscolumn_lnum*
    `require("organ.fold.contents").statuscolumn_lnum(lnum, relative)`
    Computes the value to render in the line-number slot for buffer
    line `lnum`, counting only VISIBLE (non-concealed) lines.
    `relative = true` returns relnum (0 on the cursor line); false
    returns the absolute lnum.  See |organ-fold-statuscolumn_marker|
    for the matching fold-marker helper and a complete recipe.

  Cleanup triggers    `BufWipeout` clears the in-memory state on
                      buffer wipe.  `FileType` (set to anything
                      other than org) calls `leave()` so window
                      options are restored if the user switches the
                      buffer's filetype mid-CONTENTS.  Explicit
                      cycle out via `<S-Tab>` calls `leave()`
                      normally.  `M.forget(bufnr)` is a hard reset
                      for any consumer that needs it.

  Fold-key overrides  `za` / `zc` / `zo` / `zM` / `zR` / `zm` /
                      `zr` are wrapped buffer-local for the
                      duration of CONTENTS state.  Per-heading keys
                      stay inside CONTENTS; foldlevel-altering keys
                      leave it.
                        - `za` on a heading: cycle that heading's
                          individual visibility (FOLDED -> CHILDREN
                          -> SUBTREE), Emacs `org-cycle`.
                        - `zc` on a heading: close that heading
                          to FOLDED state.
                        - `zo` on a heading: open that heading
                          fully (SUBTREE state).
                        - `zM` / `zR` / `zm` / `zr` (anywhere) and
                          `za` / `zc` / `zo` off a heading: leave
                          CONTENTS first and then re-feed the key
                          so vim's default OR the user's prior
                          mapping takes over.

                      Any buffer-local mapping the user already had
                      for these keys is snapshotted on enter and
                      restored verbatim on leave (rhs / callback /
                      silent / noremap / expr / desc).  Global
                      mappings always return automatically once
                      the buffer-local override is removed.

                      Hard limit: a NON-RECURSIVE alias --
                      `:nnoremap <X> za` -- bypasses every mapping
                      including ours when `<X>` is pressed.  The
                      override fires on direct `za` and on
                      recursive aliases (`:nmap <X> za`) but vim's
                      mapping system gives no hook to intercept a
                      `nnoremap`'d play of the same key.  This is
                      a vim-level constraint, not an organ bug.
                      For bullet-proof coverage on alternate keys,
                      use the Lua entry point (next).

                                        *organ-fold-contents-view-fold_action*
    `require("organ.fold.contents").fold_action(key)`
    Public dispatcher with the same logic as the buffer-local
    overrides above.  Outside CONTENTS state it just feeds `key`
    so the user's normal fold behavior runs.  Map any key to it
    and the right thing happens regardless of recursion settings:
    >lua
        vim.keymap.set("n", "<F3>", function()
          require("organ.fold.contents").fold_action("za")
        end)
<
    `key` is one of the strings organ wraps in CONTENTS:
        za | zc | zo | zM | zR | zm | zr

                                          *organ-fold-contents-view-is_active*
    `require("organ.fold.contents").is_active(bufnr)`
    True iff CONTENTS extmarks + state are present for `bufnr`.
    Wrap your own custom logic with `if contents.is_active(0) then
    ... end` to scope behavior to CONTENTS without touching any
    mapping.

  relnum helper       `statuscolumn_lnum(lnum, relative)` counts
                      closed folds as a single visible row and
                      skips conceal-extmark rows entirely, so a
                      heading 5 buffer rows past a closed
                      property drawer renders as `1` (visually
                      adjacent), not `5`.  See
                      |organ-fold-contents-view-statuscolumn_lnum|.

In-process language server for org buffers.  When enabled, every
org buffer gets an in-process LSP client attached automatically

                                  link target preview

                                  update inbound links
    `textDocument/documentSymbol` outline tree (aerial,
                                  symbols-outline, navic, ...)
    `workspace/symbol`             cross-file fuzzy outline find
    `textDocument/completion`      headlines, IDs, tags, TODO
                                  keywords, link targets
    `textDocument/foldingRange`    LSP-driven folding
    `textDocument/documentLink`    clickable links
    `textDocument/codeAction`      same set as |:Org-actions|
    `textDocument/diagnostic`      malformed planning lines,

    `textDocument/formatting`      `vim.lsp.buf.format()` runs
                                  |:Org-format|

                                                    *organ-config-lsp-enabled*

    A running client can also be stopped at any time with

*:Org-habits*

*:Org-export_markdown*
    `:Org export markdown[!] [path]`
    Export the current org buffer to CommonMark. Without `path`, writes
    to the buffer's filename with `.org` replaced by `.md`. Use `!` to
    overwrite an existing target.

    Conversions:
        `* heading`         → `#`-style ATX header (level mapped 1:1)
        `*bold*`            → `**bold**`
        `=verb=` `~code~`   → `` `code` ``
        `[[t][d]]`          → `[d](t)`

        `-----`             → `---` (thematic break)

    Export the current org buffer to a self-contained HTML5
    document. Writes to `<basename>.html` by default; bang to
    overwrite. Maps the same constructs as `:Org export markdown`
    plus:
        `[ ]` `[X]`         → `<input type="checkbox" disabled>`
        tables              → `<thead>` / `<tbody>` with `<th>` / `<td>`

        title (#+title)     → `<title>` and document head

    A small inline `<style>` block ships by default for sane

Agenda alarms                                                   *organ-alarms*

Notify before each scheduled time today (or fire your own callback).
Disabled by default; opt in with: >

    require("organ").setup({
      alarms = { enabled = true },
    })
<
Defaults:
    `lead_minutes`           `{ 10, 0 }` — fire 10 min before and at due time
    `scan_interval_seconds`  `600`       — rescan today's agenda every 10 min
    `notify`                 nil          — use vim.notify with a default body

Custom callback: >

    require("organ").setup({
      alarms = {
        enabled = true,
        lead_minutes = { 30, 5, 0 },
        notify = function(row, lead, fire_ts)
          -- row.title, row.id, row.scheduled (ISO), row.file_path, row.line_start
          -- lead is the configured `lead_minutes` slot that triggered.
          require("notify")("Org due: " .. row.title, "warn")
        end,
      },
    })
<
Implementation: each scan walks today's `:Org agenda` and creates a libuv
timer per (headline × lead). On the `indexed` event (after `:Org scan` or
file save), the schedule is recomputed so freshly added rows are picked
up. DONE / CANCELLED rows and past-due-minus-lead rows are skipped.

Speed commands                                          *organ-speed-commands*

When the cursor sits at column 0 of a headline, single-key bindings can
dispatch common operations without prefixes. This is the Neovim port of
Emacs `org-use-speed-commands`. Disabled by default; opt in with: >

    require("organ").setup({
      speed = { enabled = true },
    })
<
Default keymap (every entry overridable per-key, or set to false):
    `n` / `p`    next / previous visible heading
    `f` / `F`    fold cycle / global fold cycle
    `t` / `T`    TODO cycle / TODO set (menu)
    `s` / `d`    schedule / deadline
    `a` / `A`    archive / archive to sibling
    `I` / `O`    clock in / out
    `<` / `>`    promote / demote
    `U` / `D`    move subtree up / down
    `g`          open agenda
    `c`          capture
    `?`          show speed-command help

Customisation: >

    require("organ").setup({
      speed = {
        enabled = true,
        commands = {
          n = "next_visible",
          p = false,           -- disable just `p`
          x = "todo_cycle",    -- rebind `x` to TODO cycle
          y = function() print("custom") end,
        },
      },
    })
<
Off-headline (or non-column-0) the keys fall through to their normal
Vim behaviour, so `n`/`p` still mean "repeat last search forward/back"
elsewhere in the buffer.

    Jump from a footnote reference to its definition (or vice versa).
    Reference forms recognised: `[fn:LABEL]`, `[fn:LABEL: text]`,
    `[fn::text]`, `[fn:N]`.

*:Org-footnote_insert*
    `:Org footnote insert`
    Insert a fresh `[fn:N]` reference at the cursor (N = next free
    integer) and a corresponding stub definition at the end of the
    buffer.  Cursor lands on the stub for editing.

*:Org-footnote_renumber*
    `:Org footnote renumber`
    Re-sequence numeric footnotes 1..K in order of first reference.
    Both references and definition lines are rewritten consistently.

Miscellaneous                                                 *organ-cmd-misc*

*:Org-set*  *:Org-toggle*  *:Org-unset*  *:Org-config*
    `:Org set <path> <value>`
    `:Org toggle <path>`
    `:Org unset <path>`
    `:Org config [effective|global|buf]`

    Per-buffer config override layer.  `set` writes a partial override
    that takes precedence over the global config for THIS buffer only;
    `toggle` flips a boolean at `<path>`; `unset` removes the buffer
    override so the global value reasserts; `config` prints the
    effective (default), global, or buf-local-only config.  Examples:

        `:Org toggle indent.enabled`        flip visual auto-indent
        `:Org set modern.bullets true`      enable per-level bullets
        `:Org toggle stars.hide`            hide leading stars
        `:Org unset modern.bullets`         revert to the global value

    Tab-completion walks the active config tree, so `:Org set <Tab>`
    enumerates every overridable path.

REPEATERS AND HABITS                                         *organ-repeaters*

A SCHEDULED or DEADLINE timestamp can carry a "repeater" suffix that
auto-bumps the date when the task transitions into a done state.

Base forms (from Emacs org-mode):
    `+N{u}`     plain repeat — bump from the OLD date by N units.
    `++N{u}`    catch-up — bump until the new date is in the future.
    `.+N{u}`    restart — bump from TODAY by N units.
where `{u}` is one of `h` (hour), `d` (day), `w` (week), `m` (month),
or `y` (year).

Habit alarm form (Emacs `org-habit`):
    `.+P/Q`     repeat every P; flag overdue when more than Q has
                passed.  P and Q each carry a unit.

Examples:
    `<2026-04-25 Sat +1w>`         every week from Apr 25
    `<2026-04-25 Sat .+1d/3d>`     daily habit, alarm if 3+ days pass
    `<2026-04-25 Sat ++1m>`        catch-up monthly

Skip filters                                          *organ-repeater-filters*

After the period, an optional bracketed filter narrows which dates the
repeater is allowed to land on.  Tokens are comma-separated; named
days/months OR-combine, every other token AND-combines.  Within a
single `KEY:VALUE` token, VALUE may be a `;`-separated OR list.

    Day classes:
        `wd`             weekday (Mon-Fri)
        `we`             weekend (Sat-Sun)
    Named days:
        `mon`,`tue`,`wed`,`thu`,`fri`,`sat`,`sun`     OR-combined
    Named months:
        `jan` … `dec`                                 OR-combined
    Day of month:
        `dom:N`          exact day (1..31)
        `dom:-N`         Nth from end (-1 = last day)
        `dom:first`      = `dom:1`
        `dom:last`       = `dom:-1`
        `bom`            alias for `dom:1`
        `eom`            alias for `dom:-1`
        `dom:N1;N2;...`  any of these days
    Nth weekday in month:
        `nth:K:DOW`      K = 1..5 or `last`; DOW = `mon`..`sun`
        `nth:K:D1;D2`    Kth occurrence of any listed weekday
    Month:
        `month:N`        N = 1..12
        `month:NAME`     short-name match (jan..dec)
        `month:V1;V2`    any of these months
    Quarter:
        `quarter:Q`      Q = 1..4
        `quarter:Q1;Q2`  any of these quarters
    Business day:
        `bizday`         weekday and not in the configured holiday
                         calendar (`todo.default_holiday_cal`)
        `bizday:N`       Nth business day of month
        `bizday:-N`      Nth from end
    Calendar:
        `cal:NAME`       in the named calendar
                         (`todo.calendars` or ISO-3166-1 alpha-2 code
                         routed through |:Org-fetch_holidays|)
    Negation:
        `!TOKEN`         negate any of the above

Examples:
    `+1d[wd]`                weekday-only daily standup
    `+1m[dom:25]`            25th of every month
    `+1m[eom]`               last day of every month
    `+1m[dom:-3,wd]`         3rd-to-last weekday of every month
    `+1m[nth:2:mon]`         2nd Monday of every month
    `+1m[nth:last:fri]`      last Friday of every month
    `+1d[bizday]`            any business day (skips weekends + holidays)
    `+1m[bizday:-1]`         last business day of every month
    `+1d[month:1;4;7;10]`    any day in Jan / Apr / Jul / Oct
    `+1d[!cal:US]`           skip US holidays

Repeater highlighting                              *organ-repeater-highlights*

Inside a timestamp, the parts highlight separately:
    `@org.timestamp.date`              YYYY-MM-DD
    `@org.timestamp.dayname`           Mon / Tue / ...
    `@org.timestamp.time`              HH:MM
    `@org.timestamp.repeater`          +1d / .+1d / ++1d
    `@org.timestamp.repeater.alarm`    /3d (org-habit alarm)
    `@org.timestamp.repeater.filter`   [wd,nth:2:fri,!cal:US]
    `@org.timestamp.warning`           -3d
    `@org.timestamp.diary`             <%%(diary-cyclic ...)>
    `@org.timestamp.range`             <a>--<b>

SOURCE-BLOCK LANGUAGE INJECTION                          *organ-src-injection*

Tree-sitter injects an embedded language parser into every
`#+begin_src LANG ... #+end_src` block whose LANG matches one of the
built-in patterns (the parser must be installed separately, e.g. via
`nvim-treesitter`):

    python, lua, bash (sh / shell / zsh), javascript (js),
    typescript (ts), rust, go, ruby, c, cpp (c++), java, html, css,

>
    ((src_block) @injection.content

     (#set! injection.language "elixir"))
<

Use |:Org-edit_special| to edit a src block in a dedicated buffer with
its language's full filetype features (LSP, formatters, etc.) and
write the result back on save.

CITATIONS                                                    *organ-citations*

Citations follow the standard org-cite syntax:

    `[cite/STYLE:PREFIX @key1 SUFFIX1; PREFIX2 @key2 SUFFIX2]`

The parser decomposes citations into named tree-sitter nodes:

    citation
      citation_style?            "/style"
      citation_reference         per `@key` block
        citation_prefix?         text before `@`
        citation_key             "@key" (alpha/digit/_/-/:)
        citation_suffix?         text after key, before `;` or `]`

Each part highlights independently:
    `@org.citation`            whole bracket
    `@org.citation.style`      style
    `@org.citation.key`        @key
    `@org.citation.prefix`     prefix text
    `@org.citation.suffix`     suffix text

ARCHITECTURE                                              *organ-architecture*

organ.nvim has three startup phases:

1. `plugin/organ.lua` — runs at Neovim startup. Registers all `:Org*`
   user commands and the `org` filetype. No DB, no tree-sitter, no I/O.
   Startup cost is negligible regardless of org file count.

2. `ftplugin/org.lua` — runs when a buffer's filetype is set to `org`.
   Delegates to `lua/organ/ftplugin/*.lua` for structure, inline-edit,
   property, table, core (TODO / fold / clock) keymaps. `setup()` must
   have run before this fires.

3. Lazy resources — the SQLite handle (`runtime.lua`) and tree-sitter
   parser are opened on first use, not at `setup()` time. `setup()`,
   |:Org-agenda|, and other non-parsing commands work immediately even
   if the grammar hasn't been built yet.

The index lives in a single SQLite database (`organ.db`). All queries
go through `cmd.lua`, which dispatches to feature modules. The schema
is versioned; `auto_recover` handles forward migration automatically.

The filesystem watcher (`lua/organ/watcher.lua`) uses `libuv` `fs_event`
by default. When a `.org` file changes, it is re-parsed incrementally
and the index updated. The watcher is optional; manual |:Org-scan| or
|:Org-index| work without it.

EMACS / ORG-ROAM INTEROP                                       *organ-interop*

organ.nvim aims for byte-level format compatibility with Emacs
org-mode and org-roam.  Files written by Emacs read back unchanged;
files written by organ are valid Emacs org.  This section documents
what's covered, what isn't, and the one config knob that matters for
sharing an org_dir between the two.

File format ~
    organ writes only standard org-mode syntax — headlines, drawers
    (`:PROPERTIES:` / `:LOGBOOK:` / `:NAME:`), planning lines
    (`SCHEDULED:` / `DEADLINE:` / `CLOSED:`), tags, footnotes, lists,
    tables, links (`[[id:...]]` / `[[file:...]]` / `[[*Title]]`),
    src blocks, captures, archive subtrees with the Emacs property
    set (`ARCHIVE_TIME` / `ARCHIVE_FILE` / `ARCHIVE_OLPATH` /
    `ARCHIVE_TODO` / `ARCHIVE_CATEGORY` / `ARCHIVE_ITAGS`), LOGBOOK
    entries, `[cite:@key]` org-cite, and timestamps in
    `<YYYY-MM-DD Day>` form.  Emacs reads these without modification.

UUID format ~
    Emacs / org-roam default to UUID v4 (random) for `:ID:` values.
    organ defaults to UUID v7 (timestamp-prefixed; sortable by
    creation order — RFC 9562).  Both are valid RFC 4122 strings, and
    `:ID:` values are opaque to org-mode — both formats interoperate
    freely.  Switching tools means new headlines pick up the new
    tool's format; old headlines keep their original IDs intact.
    To force v4 generation in organ:
>lua
        require("organ").setup({
          links = {
            id_method = function() return require("your-v4-lib").v4() end,
          },
        })
<
    Or set `id_method = "ts"` for the timestamp-string form
    (`YYYYMMDDTHHMMSS-NNN`) instead of either UUID flavor.

ID locations file ~
    Emacs's org-id resolves cross-file `[[id:...]]` links via
    `~/.emacs.d/.org-id-locations` (an s-expression alist mapping
    files → ID lists).  organ uses its SQLite index instead.  When
    you share an org_dir between Emacs and organ, point organ at the
    same file:
>lua
        require("organ").setup({
          links = { id_locations_file = "~/.emacs.d/.org-id-locations" },
        })
<
    With this set, organ exports the index to that file after every
    scan (`scan_done` event hook).  Emacs's
    `org-id-locations-load` reads it on startup so cross-file ID
    links resolve in both tools without a full directory scan.
    Manual export: `:Org id export_locations`.

Reserved hierarchical action names ~
    organ's `:Org` dispatcher uses sub-action names under the
    `agenda` group (`day`, `week`, `todos`, `tags`, `search`,
    `custom`).  If you name a configured agenda view exactly the
    same as one of these, the hierarchical action wins — pick a
    distinct view name.  Same for `find {file, link, ref, tag,
    todo}`, `roam {insert, daily, buffer, linkify, graph}`, etc.

Known interop limitations ~
    - Emacs babel `:session` headers carry across blocks via
      Emacs's process pool; organ has its own session manager
      (`organ.babel.sessions`) that supports python / sh / bash /
      zsh — other languages currently re-evaluate per block.
    - LaTeX environments are recognised by the indexer but render-
      side support is limited to `latex_preview` / `latex_render`.
    - Emacs `org-link-frame-setup` for `gnus` / `bbdb` / `info` is
      not wired (organ.link.dispatch falls back to `:open`).

DIFFERENCES FROM EMACS                                     *organ-differences*

Intentional differences from Emacs org-mode / org-roam:

Clock-in with active clock ~
    Emacs: Prompts keep / stop / cancel.
    organ.nvim: Auto-stops current, starts new (with notification).
    Why: Single-clock UX; prompt is friction.

Clock report default range ~
    Emacs: All time.
    organ.nvim: Current week (Mon–Sun).
    Why: Smaller surface; use args for other ranges.

Clock persist file ~
    Emacs: `org-clock-persist-file`.
    organ.nvim: `<stdpath data>/organ/clock.json`.
    Why: Same idea, Neovim-native path.

Property-value link match ~
    Emacs: Pattern-based.
    organ.nvim: Token-membership exact match.
    Why: Clearer semantics, no false positives on ROAM_REFS.

Property key case ~
    Emacs: Lenient.
    organ.nvim: Case-sensitive.
    Why: Avoid `:Title:` matching `[[title:...]]`.

TODO repeater skip filters ~
    Emacs: No calendar awareness.
    organ.nvim: `+/++/.+` extended with `[wd | we | dow-list | cal:NAME]`.
    Why: Superset — weekday-only, weekend-only, holiday-aware repeats.

Datetree headline format ~
    Emacs: Hardcoded year / year-month / year-month-day.
    organ.nvim: Configurable via |organ-config-capture-datetree_format|.
    Why: Weekly-grouped and flat journals supported.

Capture buffer keymaps ~
    Emacs: `C-c C-c` finalise, `C-c C-k` cancel (non-modal).
    organ.nvim: `ZZ` finalise, `ZQ` cancel, `<CR>` confirm.
    Why: Vim-native. Emacs bindings are an opt-in config recipe.

Subtree manipulation keymaps ~
    Emacs: `M-Left/Right`, `M-S-Left/Right`, `M-S-Up/Down`.
    organ.nvim: `<<` / `>>` / `<LocalLeader></>` / `gK` / `gJ`.
    Why: Neovim-native. Emacs bindings are opt-in.

Inline increment/decrement ~
    Emacs: `S-Left/Right/Up/Down`.
    organ.nvim: `<C-a>` / `<C-x>` (extends Vim's number increment).
    Why: Reuse Vim's canonical increment keys.

Table editing realign trigger ~
    Emacs: `|` typing AND `<Tab>`.
    organ.nvim: `<Tab>` only.
    Why: Keystroke-noise reduction.

Table row/col operations ~
    Emacs: `M-S-Up/Down/Left/Right`.
    organ.nvim: `<LocalLeader>|` menu or `:Org table_*` commands.
    Why: One discoverable menu vs. 8 separate keys.

Spreadsheet formula engine ~
    Emacs: Full Emacs Calc (lookups, remote refs, lisp).
    organ.nvim: Subset: `$N`/`@R`/`@R$N`, ranges, arithmetic,
    `vsum/vmean/vmax/vmin/vlen`.
    Why: Practical 80%; full Calc rarely needed in Neovim workflows.

Agenda multi-view dispatcher ~
    Emacs: Always shows dispatcher.
    organ.nvim: Shows `vim.ui.select` only when `agenda.views` is
    non-empty; single-view users get zero friction.
    Why: No modal overhead for single-view users.

Find headline filter ~
    Emacs: Plain-text title/tag search.
    organ.nvim: Prefix tokens `todo:NEXT priority:A tag:work file:inbox`
    AND plain title words.
    Why: Better than Emacs — structured multi-criteria in the prompt.

Find backlink count ~
    Emacs: Not shown.
    organ.nvim: `(←N)` column with inbound id-link count per headline.
    Why: Matches org-roam centrality UX without org-roam dependency.

Agenda jump keymaps `o`/`v` ~
    Emacs: Bare `o` opens in another window; `v` chooses view options.
    organ.nvim: `gs`/`gv` (vim "go" namespace).
    Why: Bare `o`/`v` shadow Vim's normal-mode `o` (open new line) and
    `v` (visual mode); muscle memory mismatch is jarring. Pinned by
    `tests/keymap_audit_test.lua`.

File-level `:ID:` (org-roam) ~
    Emacs org-roam: A property drawer BEFORE the first heading creates
    a file-level node, addressable as `[[id:UUID]]`.
    organ.nvim: Same behavior. The indexer surfaces a synthetic
    level-0 record so `query.get_by_id` / agenda / find / backlinks
    all work uniformly with file-level IDs. Pinned by
    `tests/roam_create_to_index_e2e_test.lua`.

NATIVE OS NOTIFICATIONS                                       *organ-notifier*

By default, agenda alarms (`alarms.enabled = true`) deliver in-Neovim
notifications via `vim.notify` — they only fire while Neovim is running.
**Strictly opt-in**: nothing is installed, registered, or scheduled until
you explicitly enable OS-level scheduling. Two paths to enable:

  1. Set `alarms.local_schedule = true` in `setup()`. The first scan
     after that installs the per-platform bundle (macOS) and starts
     scheduling.
  2. Run `:Org notifier install` directly (macOS) for explicit install
     without enabling `local_schedule` (e.g. just to test).

>
    require("organ").setup({
      alarms = {
        enabled = true,
        local_schedule = true,    -- opt-in: route reminders through OS
        lookahead_hours = 48,     -- pre-schedule horizon (default 48)
      },
    })
<

How it works (macOS, post-redesign): ONE persistent LaunchAgent
(`sh.organ.tick`) whose plist carries an array of exact-time triggers
— one per upcoming reminder. launchd wakes the agent at each of those
times and only those times, so:

  - System Settings → Login Items & Extensions has ONE entry
    ("Organ"), regardless of how many reminders you have scheduled.
  - Zero polling: between fires, the process doesn't run at all.
  - Survives reboot (launchd persists agents across logout/boot).

The agent invokes a bundled native binary that uses macOS's modern
`UNUserNotificationCenter` API. Notifications attribute to "Organ"
(the bundle id `sh.organ.notifier`), so you grant permission to
"Organ" in System Settings → Notifications, not "Script Editor".

Per-platform mechanism:

  macOS    Single tick LaunchAgent + Swift `organ-notify` binary at
           `~/Library/Application Support/organ/Organ.app/`. If `swiftc`
           is missing (no Xcode CLT), falls back to a shell script that
           calls osascript — notifications still fire but attribute to
           Script Editor. `:Org notifier doctor` reports which is in use.
  Linux    `at(1)` if `atd` is running, else `systemd-run --user`.
           Delivery via `notify-send --app-name=Organ --icon=organ`.
  Windows  `Register-ScheduledTask` + WinRT toast via PowerShell. First
           run installs %APPDATA%\organ\ + a Start Menu shortcut with
           AppUserModelID set so toasts say "Organ" instead of
           "Windows PowerShell".

What gets installed and where (macOS): ~

  Path                                                       What
  --------------------------------------------------------- ----------------
  ~/Library/Application Support/organ/Organ.app/            App bundle
    Contents/Info.plist                                     Bundle metadata
    Contents/MacOS/organ-notify                             Swift binary (or
                                                            shell fallback)
    Contents/Resources/Organ.icns                           Icon
  ~/Library/LaunchAgents/sh.organ.tick.plist                Tick agent
  ~/Library/Logs/organ-notifier.log                         Tick stderr log

Linux uses system tools only — no bundle install. Windows writes
`%APPDATA%\organ\` (icon + notify helper script + Start Menu shortcut).

Commands ~

*:Org-notifier_install*
    `:Org notifier install`
    Explicit, opt-in install of the macOS notifier bundle. Builds the
    Swift `organ-notify` binary (requires Xcode CLT for native
    attribution; falls back to a shell wrapper otherwise), writes
    Info.plist + icon, and registers the bundle with macOS
    LaunchServices. Idempotent. No-op on Linux/Windows.

*:Org-notifier_test*
    `:Org notifier test`
    Fire a one-off test notification 10 seconds from now via the
    platform backend. On macOS, requires `:Org notifier install` to have
    run first (errors out with a clear message otherwise — never
    silently installs as a side effect of "test").

*:Org-notifier_status*
    `:Org notifier status`
    Per-platform diagnostic: detected scheduler tools, current scheduled
    entry count, next fire time, bundle install state.

*:Org-notifier_doctor*
    `:Org notifier doctor`
    Walks every link in the chain (tools, bundle, LaunchServices
    registration, foreground notification probe) and reports PASS / FAIL
    for each. Run this when notifications aren't firing.

*:Org-notifier_clear*
    `:Org notifier clear`
    Cancel every scheduled reminder. Bundle stays installed.

*:Org-notifier_uninstall*
    `:Org notifier uninstall`
    macOS only. Confirms before doing anything; then removes the tick
    agent, every legacy per-reminder agent (from the old design),
    deletes the bundle dir, deregisters from LaunchServices, and
    nudges cfprefsd so System Settings refreshes. Refuses to delete
    if the bundle path is a SYMLINK (paranoia guard against following
    somewhere unexpected).

Known limitations ~
  - Linux without `atd`: `systemd-run` transient timers don't survive
    reboot.
  - Notification permission: every platform has a one-time prompt the

MACROS, SETUPFILE, INCLUDE                                  *organ-cmd-expand*

Org-mode's reusable-content surface — macros (`{{{name(args)}}}`),
SETUPFILE keyword inheritance, and INCLUDE directives — is implemented
by `lua/organ/expand.lua`. The expansion runs as a buffer pre-pass
before tree-sitter parses the source. Built-in macros: `{{{date(FMT)}}}`,
`{{{time(FMT)}}}`, `{{{modification-time(FMT)}}}`, `{{{title}}}`,
`{{{author}}}`, `{{{email}}}`, `{{{date}}}` (no-arg pulls #+DATE),
`{{{property(KEY)}}}`, `{{{keyword(KEY)}}}`, `{{{n(VAR[,VAL])}}}`
counters.

*:Org-expand_preview*
    `:Org expand_preview`
    Open a scratch buffer with the rewritten text — SETUPFILE pulled
    in, INCLUDEs inlined, macros expanded. No export round-trip
    required. Cycle detection caps at 8 passes for self-referential
    macros.

Export integration: pass `opts.expand = true` to any export backend
(`:Org export markdown`, `:Org export html`, etc.) to run the full
SETUPFILE → INCLUDE → MACRO pass before tree-sitter parses the source.

INCLUDE forms recognised:
  `#+INCLUDE: "path"`                          verbatim insert
  `#+INCLUDE: "path" example`                  wrap in `#+begin_example`
  `#+INCLUDE: "path" src LANG`                 wrap in `#+begin_src LANG`
  `#+INCLUDE: "path" export FMT`               wrap in `#+begin_export FMT`
  `#+INCLUDE: "path" :lines "5-10"`            slice
  `#+INCLUDE: "path::*Headline"`               subtree extraction
  `#+INCLUDE: "path::#NAME"`                   named-block extraction
  `#+INCLUDE: "path" :minlevel N`              promote subtree to level N

Recursive transitive INCLUDEs are supported.

TODO DEPENDENCIES + ORDERED                               *organ-cmd-todo-ext*

`lua/organ/dependencies.lua` enforces three guards at every TODO state
transition (wired into `todo._apply`):

  - Parent blocked by children: a headline can't transition to DONE
    while any descendant is in an active TODO state. Mirrors Emacs
    `org-enforce-todo-dependencies = t`. Default ON; disable via
    `todo.enforce_dependencies = false`.
  - ORDERED siblings: a headline whose parent has `:ORDERED: t` cannot
    transition to DONE while any previous sibling is still active.
  - Checkbox dependencies (opt-in): with
    `todo.enforce_checkbox_dependencies = true`, a headline cannot
    transition to DONE while any `- [ ]` in its body is unchecked.

A child carrying `:NOBLOCKING: t` is exempt from the parent-blocking
guard.

*:Org-toggle_ordered*
    `:Org toggle_ordered`
    Flip the `:ORDERED:` property on the headline at cursor. When set,
    sibling-dependency enforcement applies to its children.

AGENDA FORMAT                                            *organ-agenda-format*

The default render mirrors Emacs's `org-agenda-prefix-format` and uses
different defaults per view kind, just like Emacs.

TODO list view (`block.kind = "todo"` or `block.from` unset): ~
>
    work:        TODO [#A] Standup                    :work:urgent:
    work:        NEXT [#B] Code review                       :work:
    work:             Untagged plain heading
    personal:    DONE Buy groceries                        :errand:
    work:             [#C] Notes for later                    :ref:
<
Flat list, `category:` prefix, no time / Scheduled: column.

Daily/weekly agenda view (`block.kind = "agenda"` or `block.from` set): ~
>
    Sunday      3 May 2026
      work:    9:00........ Scheduled:  TODO [#A] Standup     :work:urgent:
<
Day-grouped, dot-padded time, `Scheduled:`/`Deadline:` tag, undated
rows hidden by default.

Customize via `organ.config.agenda`:

`agenda.prefix_format` ~
    One of:
      * string — applied to every block regardless of kind. Mini-format
        language (see specifiers below). Same as Emacs's single-format
        `org-agenda-prefix-format`.
      * table — keyed by view kind. Default:
>lua
        {
          agenda  = "  %-12:c %?-12t %?s ",
          todo    = "  %-12:c ",
          stuck   = "  %-12:c ",
          default = "  %-12:c ",
        }
<
      * function — `function(record, ctx) -> string` for full control.
    Format specifiers (string or per-kind table values):
        %c       category (filename stem unless `#+CATEGORY:` set)
        %-Nc     category, left-padded to N chars
        %-N:c    category followed by `:`, padded to N chars total
                 (matches Emacs's `%-12:c` modifier)
        %t       scheduled time (e.g. `9:00` — no leading zero)
        %-Nt     time, dot-padded to N chars (Emacs's distinctive style:
                 `9:00......`)
        %?-Nt    time, rendered as N spaces when empty (so the column
                 stays aligned even for un-timed rows; matches Emacs `%?`)
        %s       scheduling tag: "Scheduled:" / "Deadline:" / ""
        %?s      same, blank when empty

`agenda.todo_width` ~
    Force the TODO column to a fixed width. Default `nil` → auto-fit to
    the longest keyword present in the rendered block (mirrors Emacs).

`agenda.tags_column` ~
    Right-align tags at this column. Default `80`. A negative value is
    treated as offset from the right edge of `textwidth` (or 80 if
    unset). Mirrors Emacs `org-agenda-tags-column`.

`agenda.show_no_date` ~
    When `false` (default) the daily/weekly agenda view hides rows that
    have no SCHEDULED / DEADLINE / CLOSED date. Mirrors Emacs's
    `org-agenda-include-all-todo = nil`. Set to `true` to surface a
    `(No date)` group like the previous behavior.

`agenda.block_separator` ~
    When `true` (default) emit a `═════` line between blocks
    in a multi-block view (like Emacs). Set to `false` to use a blank
    line separator instead.

`agenda.category_width`, `agenda.time_width` ~
    Numeric widths for the default `%-Nc` / `%?-Nt` placeholders when the
    user keeps the default `prefix_format`. Override either to change the
    visual column width.

BABEL SESSIONS                                          *organ-babel-sessions*

`:session foo` header on a `#+begin_src python` (or `sh` / `bash`)
keeps a long-lived REPL alive between blocks; variables and imports
carry across. The literate-programming workflow.

>org
    #+begin_src python :session main
    import math
    x = 7
    #+end_src

    #+begin_src python :session main
    print(math.sqrt(x))   #=> 2.6457513...
    #+end_src
<
Different `:session` names spawn independent kernels. Drop a session
explicitly with: >lua
    require("organ.babel.sessions").stop_session("python", "main")
<
or stop all: >lua
    require("organ.babel.sessions").stop_all()

ORG-MODERN VISUAL UPGRADES                                      *organ-modern*

Four composable visual stages that decorate org buffers, all opt-in: >lua
    require("organ").setup({
      modern = {
        bullets = true,    -- per-level glyphs
        blocks  = true,    -- block-frame decoration
        pills   = true,    -- TODO + timestamp pills
        table   = true,    -- pipe-table conceal + virtual borders
      },
    })
<
                                                        *organ-modern-bullets*
`bullets` — replaces the trailing `*` of each headline with a level-
indexed glyph (◉ ○ ◈ ◇ default cycle, repeats for deeper levels) and
conceals the leading N-1 stars as spaces. Override the cycle: >lua
    modern = { bullets = { glyphs = { "●", "○", "▶", "▷" } } }
<
DO NOT combine with `stars.hide = true` — both touch the same conceal
range and the last-applied wins (non-deterministic).

                                                         *organ-modern-blocks*
`blocks` — `#+begin_TYPE [args]` and `#+end_TYPE` lines render as box-
drawing decoration (`┌── lang ──`, `└──`). Works for src/quote/example
/verse/export/comment/special/greater. Original text is concealed;
underlying buffer content unchanged.

                                                          *organ-modern-pills*
`pills` — TODO state keywords and timestamps render with `reverse =
true + bold` overlay so they look like solid color blocks. Cosmetic
only (no buffer text changes). The pill background comes from the
existing fg color of the @org.todo / @org.timestamp groups via vim's
inverse-video, so a single colorscheme override propagates.

                                                          *organ-modern-table*
`table` — pipe-table conceal: `|` -> `│`, `-` -> `─`, `+` -> `┼`, with
smart edge corners on rule rows and optional `┌─┬─┐` / `└─┴─┘` virtual
top/bottom borders. Org alignment-row markers (`<l>`/`<r>`/`<c>`)
collapse to `←` / `→` / `·` arrows. Pauses redraw during insert mode
by default so typing inside cells doesn't flicker.

Bool form (defaults): >lua
    modern = { table = true }
<
Override form: >lua
    modern = {
      table = {
        preset              = "light",   -- "light"|"round"|"heavy"|"double"
        border_virtual      = true,      -- top/bottom virtual borders
        alignment_indicator = true,      -- <l>/<r>/<c> -> ←/→/·
        pause_in_insert     = true,      -- skip redraw while in insert mode
      },
    }
<

STAR CONCEALMENT                                                 *organ-stars*

Emacs `org-hide-leading-stars` equivalent. Off by default. >lua
    stars = { hide = true }
<
Conceals all but the trailing `*` of each headline's leading-star
block, so `*** Foo` renders as `   * Foo`. Sets the window's
`'conceallevel'` to 2 on attach (restored on detach).

AGENDA EMACS-PARITY                                      *organ-agenda-parity*

The agenda subsystem mirrors Emacs `org-agenda` for daily-driver flows.
This section enumerates the parity work; see |organ-cmd-agenda-ext| for
the command list.

INTERACTIVE DISPATCHER                                 *organ-agenda-dispatch*
    `:Org agenda` with no args opens an Emacs-style chooser (M-x
    org-agenda):
        a   Week agenda
        d   Day agenda
        t   Global TODO list
        m   Tag query…
        s   Search by string…
        #   Stuck projects
        <user views from agenda.views config>
        default

NEW VIEWS                                                 *organ-agenda-views*
    `:Org agenda todos`            global active TODOs
    `:Org agenda tags [query]`     org-match tag-query view
    `:Org agenda search [query]`   title-substring search

PER-ROW EDIT KEYMAPS                                  *organ-agenda-edit-keys*
    + / - / =      raise / lower / clear priority
    gT             set tags
    A              archive row to file
    gA             toggle showing archived rows
    gC             open clock report
    <M-CR>         add new TODO heading

BULK SELECT + ACTIONS                                      *organ-agenda-bulk*
    <Space>        toggle bulk mark on cursor row + advance
    gM             toggle mark on every visible row
    gB             apply action menu (state change / schedule /
                   deadline / refile / archive / delete)
    u              undo last bulk delete (vim-native)
    <C-r>          redo last undone delete

PERIOD + NAVIGATION                                         *organ-agenda-nav*
    f / b          next / prev period
    .              today
    gj             jump to date
    gd / gw        day / week view

VISUAL                                                   *organ-agenda-visual*
    `time_grid`         Emacs `org-agenda-use-time-grid`. Default ON
                        for today's bucket only:
                          { hours = { 8, 10, 12, 14, 16, 18, 20 },
                            on    = "today" | "all" }
                        Set `false` to disable.
    `now_marker`        "← now" line on today's bucket. Default true.
    `view_header`       "Day-agenda (Wnn):" / "Week-agenda (Wnn):"
                        top-of-buffer line. Default true.
    `sticky`            Reuse the same agenda buffer when opening
                        the same view name again. Default true.
    `show_overdue_scheduled`
                        Roll overdue scheduled rows into today's
                        bucket. Default false (matches Emacs).

REPEATER EXPANSION                                    *organ-agenda-repeaters*
    Recurring tasks (`+1d`, `++1w`, `.+1d`, `.+7d`, ...) generate
    one synthetic row per occurrence in the agenda window. Daily
    habits show on each day Mon-Sun; weekly tasks show each week.

PREFIX FORMAT                                            *organ-agenda-prefix*
    Default per-view-kind:
        agenda  → "  %-12:c %?-12t %?s "
        todo    → "  %-12:c "
        stuck   → "  %-12:c "
    The `%s` token produces context-aware labels:
        "Scheduled:"    today's scheduled rows
        "Deadline:"     today's deadlines
        "In   N d.:"    future scheduled / deadline within 14 days
        "Sched. Nx:"    overdue scheduled (N repeat-cycles late)
        "Past due:"     overdue deadlines
    For day-grouped views, the reference date is the BUCKET's date,
    not today — Tuesday's row reads "Scheduled:" because Tuesday IS
    its scheduled day, not "In 1 d.:" relative to today.

CATEGORY + TAG ORDER                                    *organ-agenda-display*
    Category respects (in this precedence): per-headline `:CATEGORY:`
    property, file's `#+CATEGORY:` keyword, then filename stem.
    Tags render in source-file order (not alphabetical).
